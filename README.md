# check-prd-code

把**需求文档**和**代码**摆在一起核对，挑出三样东西：

- 需求里写了、代码里没做的
- 代码里做了、跟需求对不上的
- 代码里做了、需求里没提的（可能是自己加戏）

产出两份报告：一份能直接交给 AI 去改，一份要人先拍板。

## 为什么不能直接把需求和代码丢给 AI 问"实现了吗"

三个原因，每个都会让报告变成废纸：

**1. 大文档喂不进去。** 单个 PRD 几万字很常见，整份塞给模型，它必然漏掉一部分，而且你没法知道漏了哪部分。

**2. 模型会编行号。** 它说"第 1234 行有这个校验"，你得能验证。验证不了的报告，没人敢照着改代码——**照着错报告改，会把本来正确的代码改坏。**

**3. 「需求没提」不等于「多余」。** 需求文档从来不写工具类、日志、配置、DTO 转换。不加限制地反查，报出来的一大半是正常代码。

这个工具的做法是：

> **能用脚本确定的，绝不交给 AI；只有"必须读懂意思"的才交给 AI；AI 说出的每句话，脚本都要回头验一遍。**

## 三步

```bash
# 第一步：把 PRD 切成块，生成"条目化任务包"
python3 check_prd_code.py extract --prd ./需求文档.md

# 第二步：读条目、建代码索引、能直接判的判掉，剩下的做成"判定任务包"
python3 check_prd_code.py compare --code ./你的工程

# 第三步：验真、合并、出报告
python3 check_prd_code.py report --code ./你的工程 --out ./报告
```

第 1 步和第 2 步各会生成一份**任务包**，需要交给 AI 处理（见 `SKILL.md`）。
AI 把结果写回指定文件后，继续跑下一条命令。

随时可以看进度：

```bash
python3 check_prd_code.py status
```

### 依赖

Python 3.9+，**只用标准库**，不需要 `pip install`。

### 可选配置

- **索引缓存**：`compare` 会按源码文件的 `mtime + size` 给索引做缓存；
  源码没动过就直接复用，跳过重扫（缓存文件 `.checkprd/compare/index_cache.json`）。
- **错误码位数**：默认按 5 位识别错误码。项目用别的位数时，加参数或设环境变量：

  ```bash
  python3 check_prd_code.py compare --code ./工程 --error-code-digits 4
  export CHECKPRD_ERROR_CODE_DIGITS=4
  ```

## 分工

| 活 | 谁干 | 为什么 |
| :--- | :--- | :--- |
| PRD 切块 | 脚本 | 纯结构问题，脚本比模型可靠 |
| 块改写成"能判对错的话" | AI | 要读懂人话 |
| 抽标识符（接口、类名、字段、错误码） | 脚本 | 模式匹配 |
| 建代码索引 | 脚本 | 数数，不需要理解 |
| 判断"接口/字段存不存在" | 脚本 | 搜得到就是搜得到 |
| 判断"这规则实现了没有" | AI | 只有这步必须靠理解 |
| 反向查"代码里多出来的" | 脚本挑 + AI 判 | |
| **验真 AI 给的引用** | **脚本** | **模型编不出不存在的代码** |
| 出报告 | 脚本 | 填模板 |

关键在那条横线：**AI 必须逐字引用代码原文和行号，脚本回头逐字比对。**
引用对不上，这条判定当场作废，转进"待确认"。

## 两份报告

```
01-待修复.md    证据齐全，可以整份交给 AI 直接照着改
02-待确认.md    拿不准的，必须人先看一眼；勾完再交给 AI 执行
```

**为什么必须分两份**：01 是要被 AI 当改造依据用的。判错就会改坏代码。
所以凡是脚本没把握、或模型引用没通过校验的，一律拦在 02。

`02` 里的条目长这样，可以直接勾：

```markdown
- [ ] 需求本来就不需要 → 删掉
- [ ] 需求漏写了 → 我去补需求文档，这条不用管
- [ ] 是通用能力 → 保留，以后别再报出来
```

也可以整份丢给 AI，让它一条条弹给你选。

## 改完重跑

改完代码再跑一遍三步，`01` 里的条目应该会消失。

**没消失说明改的位置不对** —— 这是这个工具最实用的地方：它给了你一个可以收敛的闭环。

## 它不查什么

写在这里，免得报告被当成万能扫描器：

- **业务逻辑类的 bug** —— 算法写错、并发问题、事务失效这类，脚本和模型都判不出来，得跑测试或者人看
- 第三方依赖的源码不在工程里，没法核对
- 需求文档没写到的功能，不算「没做」
- 需求本身写错的地方，工具会以需求为准（它不知道需求是错的）

## 安装

这是一个 AI skill（`SKILL.md`）+ 命令行工具的组合。**要整目录安装** ——
脚本与 `SKILL.md` 必须同目录，只软链 `SKILL.md` 会找不到脚本。

```bash
./install.sh                     # 自动挑选已存在的 skills 目录
./install.sh ~/.claude/skills    # 或显式指定目标目录

# 等价的手动方式：整目录软链
ln -s "$(pwd)" ~/.agents/skills/check-prd-code
```

常见的 skills 目录：`~/.agents/skills`、`~/.config/opencode/skills`、
`~/.claude/skills`、`~/.codebuddy/skills`。装好后，说「核对需求和代码」这类话会自动触发。

不装 skill 也能用：直接按上面「三步」在仓库里跑即可。
